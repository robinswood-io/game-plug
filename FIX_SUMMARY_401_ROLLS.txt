RESOLUTION: 401 Unauthorized Errors on POST /api/rolls
================================================================================

ISSUE:
Users received "Error: API request failed: POST /api/rolls - 401 Unauthorized"
when attempting to record dice rolls from enhanced-character-card component.

ROOT CAUSE:
1. Duplicate RollsControllers for endpoint /api/rolls:
   - /apps/backend/src/modules/dice/rolls.controller.ts (with JwtAuthGuard)
   - /apps/backend/src/modules/rolls/rolls.controller.ts (with JwtAuthGuard)

2. Module registration order made DiceModule's RollsController active first
3. This controller had @UseGuards(JwtAuthGuard) - required authentication
4. But rolling dice is a public game mechanic - shouldn't require strict auth

SOLUTION APPLIED:
================================================================================

Step 1: Removed Duplicate Controller
   - Deleted: /apps/backend/src/modules/dice/rolls.controller.ts
   - Reason: Eliminated collision, made architecture cleaner

Step 2: Updated DiceModule
   - File: /apps/backend/src/modules/dice/dice.module.ts
   - Change: Removed RollsController from controller list
   - Result: Only RollsModule's RollsController is now active

Step 3: Made Rolls Endpoint Public
   - File: /apps/backend/src/modules/rolls/rolls.controller.ts
   - Removed: @UseGuards(JwtAuthGuard) class-level decorator
   - Removed: @ApiBearerAuth() class-level decorator
   - Result: Endpoint now accepts unauthenticated requests
   - userId: Still optional - works with authenticated or anonymous users
